## 1. Executive Summary

### 1.1 Platform Context

**Paddock** is a local-first platform for managing a small farm operation. The Planner module joins the existing module ecosystem:

| Module | Purpose | Status |
|--------|---------|--------|
| **Grow** | Microgreens experiment tracking | Production |
| **Propagation** | Plant propagation tracking | Production |
| **Planner** | Crop calendar & succession planning | **This PRD** |
| Sales | Orders, invoicing, payments | Future |
| Markets | Stall planning, inventory, schedules | Future |
| CRM | Restaurant & customer relationships | Future |
| Finance | Costs, revenue, projections | Future |

This PRD covers the **Planner** module - a crop calendar for scheduling, tracking, and managing growing activities across Grow (microgreens) and Propagation modules.

### 1.2 Problem Statement

A small farm operator managing microgreens trays and plant propagation batches needs a unified calendar to:
- Schedule sowing, harvesting, watering, and inspection tasks for microgreens trays
- Schedule cutting, rooting checks, potting up, and hardening off for propagation batches
- See at a glance what is due today, what is overdue, and what is coming up
- Link calendar events to actual trays and batches for cross-module navigation
- Plan succession planting to maintain continuous supply

Currently, scheduling is implicit in tray/batch data (sow dates, expected harvest dates) with no unified calendar view, leading to:
- Missed tasks (watering, rooting checks)
- No forward visibility on workload
- Inability to plan succession planting
- No cross-module scheduling overview

### 1.3 Solution

The Planner module provides:
- **Calendar View**: A full-featured calendar (month, week, day, agenda) using react-big-calendar
- **Event CRUD**: Create, read, update, and delete scheduled activities
- **Status Lifecycle**: Events flow through scheduled -> pending -> completed/skipped/cancelled
- **Cross-Module Linking**: Events can be linked to Grow trays or Propagation batches
- **Filtering & Sorting**: Filter by event type, status, site, and date range
- **Auto-Generation** (future): Automatically create events from tray/batch lifecycle milestones

## 2. Domain Model

### 2.1 Core Entity: PlannerEvent

The `PlannerEvent` is the central entity of the Planner module:

```typescript
interface PlannerEvent {
  id?: string;

  // Core Fields
  title: string;
  eventType: PlannerEventType;
  scheduledDate: Date;
  completedDate?: Date;
  status: PlannerEventStatus;

  // Optional Linking (at most one)
  speciesId?: string;        // Link to variety/species config
  trayId?: string;           // Link to GrowTray
  batchId?: string;          // Link to PropBatch

  // Location Context
  siteId: string;            // Required: FK to GrowSite
  stationId?: string;        // Optional: FK to PropStation

  // Additional Data
  notes?: string;

  // Auto-generation tracking
  isAutoGenerated: boolean;
  sourceType?: 'tray' | 'batch';
  sourceId?: string;

  // Timestamps
  createdAt: Date;
  updatedAt: Date;
}
```

**Key Invariants:**
- At most one of `trayId` or `batchId` can be set (mutual exclusivity)
- `siteId` is always required for location context
- `isAutoGenerated` events are derived from trays/batches (future feature)

### 2.2 Event Status Lifecycle

Events progress through these states:

```
                    +-----------+
                    | scheduled |  (future event, not yet due)
                    +-----+-----+
                          |
                    +-----v-----+
                    |  pending  |  (due today or overdue)
                    +-----+-----+
                          |
              +-----------+-----------+
              |           |           |
        +-----v---+  +---v-----+  +--v------+
        | completed|  | skipped |  |cancelled|
        +----------+  +---------+  +---------+
```

- **scheduled**: Future event, not yet due
- **pending**: Due today or overdue, needs action
- **completed**: Successfully completed (sets `completedDate`)
- **skipped**: Deliberately skipped, not applicable
- **cancelled**: No longer needed, removed from schedule

### 2.3 Event Types

Events are categorized by module origin:

| Event Type | Module | Description | Color |
|-----------|--------|-------------|-------|
| `sow` | Grow | Sowing new tray | Green (#22c55e) |
| `blackout_end` | Grow | Move tray to light | Yellow (#eab308) |
| `harvest` | Grow | Harvest tray | Orange (#f97316) |
| `water` | Grow | Watering task | Blue (#3b82f6) |
| `inspection` | Grow | Quality check | Violet (#8b5cf6) |
| `take_cuttings` | Propagation | Take new propagules | Teal (#14b8a6) |
| `rooting_check` | Propagation | Check rooting progress | Cyan (#06b6d4) |
| `pot_up` | Propagation | Move to individual pots | Blue (#3b82f6) |
| `harden_off` | Propagation | Begin hardening | Indigo (#6366f1) |
| `graduation` | Propagation | Ready for sale/planting | Purple (#a855f7) |

| `other` | General | Catch-all | Slate (#64748b) |

### 2.4 Enriched Events (Computed Fields)

At runtime, events are enriched with computed fields for UI display:

```typescript
interface PlannerEventWithComputed extends PlannerEvent {
  daysUntil: number;       // Days until scheduledDate (negative if past)
  isOverdue: boolean;      // Past scheduledDate and active status
  isPending: boolean;      // Due today and active status
  displayColor: string;    // Based on eventType, status, and overdue state
}
```

Display color logic:
- Terminal statuses (completed/cancelled/skipped) -> gray (#9ca3af)
- Overdue events -> red (#ef4444)
- Otherwise -> event type color

## 3. Core Features

### 3.1 Calendar View (PlannerCalendar)

The primary interface is a full-featured calendar powered by `react-big-calendar`:

- **Views**: Month, Week, Day, Agenda
- **Navigation**: Back/Next buttons, Today button
- **Event Display**: Color-coded by event type with custom CalendarEvent component
- **Slot Selection**: Clicking a date cell navigates to event creation with pre-filled date
- **Event Click**: Opens EventDetailModal with quick-view and actions
- **Filtering**: Toggle show/hide completed events
- **Event Count**: Displays count of visible events
- **Date Localizer**: Configured with date-fns, Australian English locale, week starts Monday

### 3.2 Event CRUD

**Create (EventCreateForm)**:
- Full-page form at `/planner/events/new`
- Pre-fills date from `?date=` query parameter (set by calendar slot click)
- Required fields: title, event type, scheduled date, site
- Optional fields: species/variety, tray ID, batch ID, notes
- Event types grouped by module (Grow, Propagation, General) in select dropdown
- Tray and batch ID fields are mutually exclusive (entering one clears the other)
- Sites loaded from Grow module's useSites store
- Auto-selects first site if none selected
- Client-side validation with error messages
- Navigates back to calendar on success

**Read (EventList)**:
- Filterable list view at `/planner/events`
- Filters: event type, status, date range (from/to)
- Sorted by scheduled date descending (newest first)
- Each row shows: type icon, title, type label, date, status badge, overdue indicator
- Empty state with "Create your first event" link
- Loading state with "Loading events..." message
- Click event row to navigate to detail view

**Read (EventDetail)**:
- Full-page detail view at `/planner/events/:id`
- Displays: icon, title, type badge, status badge, overdue/auto-generated indicators
- Details grid: scheduled date, completed date, site ID, species
- Days until / days overdue counter for active events
- Notes section (if present)
- Linked entity section with navigation buttons (View Tray / View Batch)
- Status action buttons (Complete, Skip, Cancel Event) for active events
- Delete button with confirmation dialog
- Metadata footer: created date, updated date, event ID
- Back navigation to event list
- "Event not found" state with link back to list

**Update**: Via status lifecycle actions (complete, skip, cancel) on EventDetail

**Delete**: Permanent deletion with confirmation dialog, navigates back to event list

### 3.3 Event Detail Modal (EventDetailModal)

Quick-view modal that opens when clicking an event on the calendar:
- Shows event details without leaving the calendar view
- Links to full EventDetail page for complete management

### 3.4 Filtering & Sorting

**Store-level filters (PlannerFilters)**:
- `siteId`: Filter by farm site (or 'all')
- `eventTypes`: Filter by one or more event types (or 'all')
- `status`: Filter by single status (or 'all')
- `showCompleted`: Toggle visibility of completed/cancelled/skipped events
- `dateRange`: Filter by date range (start/end) or null

**Store-level sorting (PlannerSort)**:
- Fields: scheduledDate, title, eventType, status
- Direction: ascending or descending
- Default: scheduledDate ascending

**Component-level filters (EventList)**:
- Type filter dropdown
- Status filter dropdown
- Date from/to inputs
- Applied locally with useMemo

## 4. Integration Architecture

### 4.1 Cross-Module Integration (usePlannerIntegration Hook)

The `usePlannerIntegration` hook provides bidirectional integration between Planner and Grow/Propagation modules:

**Create Operations:**
- `createTrayFromEvent(options)`: Creates a Grow tray from a planner event, links them, sets event to pending
- `createBatchFromEvent(options)`: Creates a Propagation batch from a planner event, links them, sets event to pending

**Event Type Validation:**
- Tray creation valid for: sow, harvest, blackout_end, water, inspection
- Batch creation valid for: take_cuttings, rooting_check, pot_up, harden_off, graduation

**Query Operations:**
- `getRelatedEvents(entityId, entityType)`: Find all planner events linked to a specific tray or batch
- `getLinkedEntityInfo(eventId)`: Get display information (type, identifier, species, status) for an event's linked entity

**Link/Unlink Operations:**
- `linkEventToTray(eventId, trayId)`: Link an event to a tray (clears batch link)
- `linkEventToBatch(eventId, batchId)`: Link an event to a batch (clears tray link)
- `unlinkEvent(eventId)`: Remove entity link from an event

**Navigation Helpers:**
- `getTrayUrl(trayId)` -> `/grow/trays/{trayId}`
- `getBatchUrl(batchId)` -> `/propagation/batches/{batchId}`
- `getEventUrl(eventId)` -> `/planner/events/{eventId}`

### 4.2 Store Dependencies

```
usePlannerIntegration
  ├── usePlannerStore (Planner events)
  ├── useTrays (Grow module trays)
  └── useBatches (Propagation module batches)
```

## 6. Data Persistence

### 6.1 Storage Architecture

The Planner module uses **Dexie.js** (IndexedDB wrapper) for local-first persistence:

- **Database**: `plannerDb` (from `@/lib/db`)
- **Table**: `plannerDb.events` stores `PlannerEvent` entities
- **In-Memory State**: Zustand store (`usePlannerStore`) maintains synchronized in-memory copy
- **Sync Pattern**: Load from DB on mount, write-through on mutations

### 6.2 State Management (usePlannerStore)

Zustand store with Dexie persistence providing:

**State:**
- `rawEvents`: Raw events from DB
- `events`: Enriched events with computed fields
- `isLoading`, `error`: Loading and error states
- `filters`, `sort`: Current filter and sort configuration

**CRUD Actions:**
- `loadEvents()`: Fetch all from DB, enrich, set state
- `createEvent(data)`: Add to DB, update state
- `updateEvent(id, updates)`: Update in DB, re-enrich state
- `deleteEvent(id)`: Remove from DB, update state
- `getEvent(id)`: Lookup by ID from enriched events

**Status Lifecycle:**
- `startEvent(id)`: Set status to pending
- `completeEvent(id)`: Set status to completed, set completedDate
- `skipEvent(id)`: Set status to skipped
- `cancelEvent(id)`: Set status to cancelled

**Linking:**
- `linkToTray(eventId, trayId)`: Set trayId, clear batchId
- `linkToBatch(eventId, batchId)`: Set batchId, clear trayId
- `unlinkEntity(eventId)`: Clear both trayId and batchId

**Selectors:**
- `getFilteredEvents()`: Apply all filters and sorting
- `getEventsByDateRange(start, end)`: Events within date range
- `getEventsByStatus(status)`: Events with specific status
- `getEventsBySpecies(speciesId)`: Events for specific species
- `getEventsBySite(siteId)`: Events at specific site
- `getEventsByTray(trayId)`: Events linked to specific tray
- `getEventsByBatch(batchId)`: Events linked to specific batch
- `getUpcomingEvents(days)`: Active events within N days
- `getOverdueEvents()`: Past-due active events
- `getEventsForDate(date)`: Events on specific date
- `getStatusCounts()`: Count by status
- `getEventTypeCounts()`: Count by event type

### 6.3 Helper Functions (usePlannerStore.helpers.ts)

Extracted for code health:
- `calculateDaysUntil(scheduledDate)`: Days until event (negative = overdue)
- `checkIsOverdue(event)`: Whether event is past due and active
- `checkIsPending(event)`: Whether event is due today and active
- `getDisplayColor(event)`: Color based on type/status/overdue
- `enrichEvent(event)`: Add computed fields to raw event
- `isSameDay(date1, date2)`: Date comparison ignoring time
- `isWithinRange(date, start, end)`: Inclusive range check

### 10.4 Design Patterns
- **Module isolation**: ErrorBoundary wrapping prevents module crashes from affecting the shell
- **Lazy loading**: Module is lazily imported in the main router
- **Write-through cache**: Zustand store syncs with Dexie on every mutation
- **Computed enrichment**: Raw DB events are enriched with computed fields on load/mutation
- **Mutual exclusivity**: Tray/batch linking enforces at most one linked entity
- **Barrel exports**: Clean import paths via index.ts files at each level
